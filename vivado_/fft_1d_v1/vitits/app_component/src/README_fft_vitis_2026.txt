FFT 512-POINT + AXI DMA: VITIS 2026.1 STARTER GUIDE
===================================================

FILES
- main_fft_dma.c: C source for a standalone application on ps7_cortexa9_0
- FFT_512_I_ip_stream_2x2_addr.h: header generated by MATLAB HDL Coder (user supplied)

WHAT THE MATLAB HEADER ACTUALLY TELLS US
- FFT IPCore_Reset register offset     0x00 (write bit0=1 for reset)
- FFT IPCore_Enable register offset    0x04 (enable bit0=1; default enabled)
- FFT IPCore_Timestamp register offset 0x08 (timestamp constant)
It does NOT define how FFT input complex numbers are packed in 32-bit TDATA,
nor scaling/order/latency. Verify using generated RTL, IP report, and golden vectors.

HARDWARE ASSUMPTIONS FROM YOUR VIVADO DESIGN
- FFT AXI4-Lite base = 0x43C00000 (VERIFY in xparameters.h)
- AXI DMA AXI4-Lite base = 0x40400000 (VERIFY in xparameters.h)
- AXI DMA = simple mode, MM2S & S2MM enabled, stream data widths 32 bits
- FFT input/output stream 32 bits and output TLAST for end of frame
- N = 512 => 2048 bytes for each transfer

CREATE APPLICATION IN VITIS UNIFIED IDE 2026.1
1. The hardware platform created from your Vivado .xsa and its standalone
   ps7_cortexa9_0 domain have already built successfully.
2. File > New Component > Application (depending on UI, use New Component).
3. Select your platform and the standalone domain of ps7_cortexa9_0.
4. Start from Empty Application (C) when available.
5. Put main_fft_dma.c in the application src folder; rename it to main.c
   or remove any other main() from template sources.
6. Put FFT_512_I_ip_stream_2x2_addr.h in the same src folder.
7. Verify xparameters.h DMA base and FFT base match the source.
8. Build the Application. The result should be an ELF. A successful build
   does not imply the DMA or FFT was executed (no board needed to build).

BEFORE RUNNING ON THE BOARD
1. Program the matching .bit/PL configuration BEFORE accessing FFT registers.
2. Ensure PS and DDR initialized (e.g. using FSBL or debugger launch config).
3. Confirm your 32-bit complex sample packing; edit FFT_REAL_IN_LOW_16.
4. Ensure the streaming output generates TLAST at the last sample.
5. Make sure your standalone app linker places TxBuffer/RxBuffer in DDR.
6. Connect UART terminal to observe xil_printf diagnostic messages.
7. Start in polling mode. In a timeout, inspect DMASR registers and waveform.
8. Do not software-reset FFT while DMA is active.

EXPECTED FIRST TEST
- The test sends one impulse, waits for both DMA channels with timeout and
  prints first 16 32-bit output words in hexadecimal.
- Output is NOT checked against a golden FFT automatically; get all 512
  words and compare numerically to MATLAB using matching fixed point, stage
  scaling and bin order before claiming a functional FFT pass.

SOFTWARE-ONLY TEST LIMITATIONS
- Code/ELF compile works without a board.
- Vitis QEMU without a PS-PL RTL co-simulation model cannot execute actual
  MMIO accesses to your custom FFT IP and real AXI DMA datapath.
- Vivado testbench is the right tool for RTL system simulation.
